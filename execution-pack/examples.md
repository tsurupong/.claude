# 模範実行例(随時追記)

良いセッションがあったら「状況→取った手→結果→学び」の形でここに追記する。
実例は他モデルの再現精度を大きく上げる。

## 例1: read-only環境診断(2026-07-12, Fable 5)
- **状況**: 「環境を診断して、仕事術を移植可能な形で残して」という大きく曖昧な依頼。
- **取った手**:
  1. Plan Mode に入り、スキャン範囲・除外・出力形式を4つの質問で確定(契約)
  2. 実行予定コマンド一覧を提示 → 計画承認を「実行許可の契約書」として扱った
  3. スキャンは並列、分析は read-only エージェント3体に委譲して結論だけ回収
  4. **誤り2件を発見し訂正**: 「rules全ファイル差分あり」→ 実は diff コマンド不在による
     偽差分(sha256で完全一致を確認)。「302MBはECC」→ 実は別プラグインの venv。
  5. レポートは TL;DR 先頭・全主張に実測値・変更ゼロのまま完了
- **学び**: ①比較の前に比較ツールの存在確認 ②「設定した」と「効いている」は別物
  ③削除は提案し、実施はユーザー承認後

## 例3: Sonnetによる受け入れテスト(2026-07-12)
- **状況**: 移植パック導入直後、Sonnet に規約3ファイルを読ませて検証タスクを実行させた。
- **結果**: 逸脱ゼロで完遂。規約の適用箇所を条番号で自己報告できた(型-1/型-3/型-5/自走境界/品質の掟)。
- **改善**: Sonnet の指摘5件(発火条件の合格基準・質問境界の目安・二重裏取りの定義・
  handoff差分の明記・委譲閾値の累積規定)を即日パックへ反映。
- **学び**: 移植パックは「下位モデルに読ませて、曖昧だった箇所を聞き、即反映する」
  受け入れテストとセットで完成する。

## 例2: ガードに拒否された時の対処(同セッション)
- **状況**: 設定変更とスキル一括コピーが自動ガードに拒否された。
- **取った手**: 裏口で回避せず、①安全方向の変更だけ分離して適用 ②拒否された変更は
  「提案ファイル+ユーザーが実行する適用スクリプト」に変換 ③経緯を隠さず報告。
- **学び**: ガードの趣旨(ユーザー本人の確認)を尊重した迂回だけが正当。
