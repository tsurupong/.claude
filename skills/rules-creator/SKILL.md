# Rules Creator

Claude Code の rules ファイルを正しい仕様・適切なスコープで作成するためのスキル。
仕様の根拠: https://code.claude.com/docs/ja/memory

## rules の仕様(要点)

- 置き場所は2つ。**ユーザールール** `~/.claude/rules/*.md`(全プロジェクト共通、プロジェクトルールより先に読み込まれ優先度は低い)と、**プロジェクトルール** `<project>/.claude/rules/*.md`(バージョン管理でチーム共有)。
- 1ファイル = 1トピック。`testing.md` `api-design.md` のような説明的なファイル名。サブディレクトリ(`frontend/` 等)も再帰的に発見される。
- YAML frontmatter の `paths:` にグロブを書くと、一致するファイルを読む時だけコンテキストに読み込まれる(条件付きルール)。`paths` なしは起動時に常時読み込み。

```markdown
---
paths:
  - "src/**/*.{ts,tsx}"
  - "tests/**/*.test.ts"
---

# API 開発ルール

- すべての API エンドポイントに入力検証を入れる
- エラー応答は標準形式を使う
```

- グロブ例: `**/*.ts`(全TS)/ `src/**/*`(src配下全部)/ `src/components/*.tsx`(特定ディレクトリ)。ブレース展開可。リテラル `[` は `\[` でエスケープ。
- ルールは「コンテキスト」であり強制ではない。**特定タイミングで必ず実行させたいものは hooks、複数ステップの手順は skill が適切** — ルールにしない。

## 手順

### 1. 内容とスコープを決める

ユーザーの依頼から以下を判断する(迷って成果物が変わる時だけ質問):

- **どこに置くか**: 全プロジェクト共通の好み → ユーザールール。プロジェクト固有・チーム共有 → プロジェクトルール。プロジェクト内で作業中に「毎回」と言われたら通常プロジェクトルール。
- **paths スコープ**: 特定のファイル種別・ディレクトリにだけ関係する内容なら `paths` を付ける。常時必要な原則(言語方針・安全境界など)は付けない。常時読み込みはコンテキストを消費するため、迷ったらスコープを付ける方向に倒す。
- **rules が適切か**: 「コミット前に必ずlint」のような強制実行 → hooks を提案。「PDFを変換する手順」のようなタスク手順 → skill を提案。それ以外の「知っておくべき規約・事実」→ rules。

### 2. 既存ルールを確認する

書く前に必ず対象ディレクトリの既存ファイルを一覧し(`ls -R`)、関連しそうなファイルを読む。

- 同トピックのファイルが既にある → 新規作成せずそこに追記・更新する。
- 矛盾する既存指示がある → 勝手に上書きせず、矛盾を提示してユーザーに確認する(矛盾したままだと Claude はどちらかを恣意的に選ぶ)。
- CLAUDE.md に同内容がある → 重複させない。移動する場合は CLAUDE.md 側の削除も提案する(削除は承認を得てから)。

### 3. ルールを書く

書き方の原則:

- **検証可能なレベルで具体的に**。「適切にフォーマットする」ではなく「インデントは2スペース」。「テストする」ではなく「コミット前に `npm test` を実行」。
- 見出しと箇条書きで構造化。1ファイルは短く保つ(目安50行以内。超えるならトピック分割)。
- 「なぜ」が自明でないルールには理由を1行添える(理由があると遵守率が上がる)。
- ファイル名は kebab-case で内容が分かるもの。既存の命名規則(番号プレフィックス等)があればそれに合わせる。

### 4. 検証と報告

- 作成後、ファイルを読み返して frontmatter(YAML として正しいか、グロブが意図通りか)を確認する。
- 報告には「作成/更新したパス」「スコープ(常時 or paths)」「次回セッションから有効になる」ことを含める。paths 付きルールは一致ファイルを読んだ時に発動する旨も伝える。
- 現在のセッションには自動反映されない点に注意(必要なら内容を今のセッションでも遵守すると宣言する)。

## 判断例

| 依頼 | 判断 |
|---|---|
| 「コミットメッセージは Conventional Commits で」 | プロジェクトルール `commit-style.md`、paths なし(git操作は特定ファイルに紐づかない) |
| 「Reactコンポーネントは関数コンポーネントのみ」 | プロジェクトルール `react.md`、`paths: ["src/**/*.tsx"]` |
| 「返答は常に日本語で」 | ユーザールール(全プロジェクト共通の好み) |
| 「push 前に必ずテストを走らせて」 | rules ではなく hooks(PreToolUse)を提案 |
| 「Excel整形の手順を覚えて」 | rules ではなく skill を提案 |
