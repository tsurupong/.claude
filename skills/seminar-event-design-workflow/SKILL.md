# セミナー・イベント設計フロー

1. **成果の定義**: 参加者が「帰りに何ができるようになるか/何を持ち帰るか」を
   1文で定義。これが決まるまで集客文・スライドに着手しない。
2. **対象者と前提**: 対象者が知っていること/知らないことを明文化
   (teaching-material-workflow の前提知識明文化と同じ要領)。
3. **構成設計**: 冒頭10分に参加者の成功体験または核心デモを置く。
   ハンズオンは「説明:手を動かす = 1:2」目安。45分ごとに休憩か場面転換。
   質疑・バッファを全体の15%確保したタイムテーブル(分単位)を作る。
4. **教材・スライド**: 配布物は teaching-material-workflow、
   スライドは frontend-slides スキルで作成。ハンズオン手順は全て
   クリーン環境相当で実行検証してから配布(検証していない手順は載せない)。
5. **集客文**: ベネフィット先行(content-workflow の媒体別展開と同じ要領)。
   日時・対象・前提知識・持ち物・環境準備を明記。
6. **運営準備**: 会場/配信の接続テスト、当日進行表、つまずき対応の想定問答、
   デモ失敗時の代替手順(録画・スクリーンショット)を用意。
7. **振り返り**: アンケート観点(理解度・再現可否・次回希望)を事前に設計し、
   終了後に改善点を記録して次回設計の入力にする。

完了条件: quality-checklist 通過+「進行表だけで1人リハーサルが通るか」の自己テスト。
