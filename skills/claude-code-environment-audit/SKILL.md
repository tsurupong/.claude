# Claude Code 環境診断(read-only)

## 手順
1. **契約**: スキャン範囲・除外・本文閲覧可否・出力形式を質問で確定。
   実行予定コマンド一覧を提示し承認を得る。承認まで一切実行しない。
2. **注入実態の確認**: 今のセッションに実際に入っている設定(CLAUDE.md/rules/スキル一覧)を
   先に記録する。「設定した」と「効いている」を区別する起点になる。
3. **スキャン**(全てread-only):
   - 構造: find / ls / du(秘匿ディレクトリは存在記録のみ)
   - 設定マップ: ~/.claude 配下(cat は設定ファイル限定)
   - 使用統計: ~/.claude.json の skillUsage / pluginUsage を jq で構造キーのみ抽出
   - プロジェクト横断: 各プロジェクトの CLAUDE.md / .claude/ / .mcp.json
4. **裏取り**: 差分・容量・帰属(どのプラグインが書いたか)は必ず二重確認。
   比較ツール自体の存在確認を忘れない(diff不在→全部DIFF事故の教訓)。
5. **分析観点**: 導入量vs使用量 / 常時注入コスト / 機能重複 / 設定と実態の矛盾 /
   安全設定(skip系フラグ・permissions有無・hooks依存度)/ メモリ系統の重複。
6. **報告**(output-style: env-audit): TL;DR→現状マップ→問題(根拠付き)→影響×工数
   →段階プラン(各Phaseにロールバックと承認ポイント)。変更はゼロのまま終える。

## 鉄則
- 変更提案と実施を必ず分離。実施は別途の明示承認後。
- 削除の代わりに「日付付きアーカイブへ移動」を提案する。
