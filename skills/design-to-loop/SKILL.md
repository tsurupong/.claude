# 設計書駆動の実装ループ

「タスクの洗い出し、タスク実施、レビュー、次の洗い出し」の反復を定型化したもの。

0. **前提確認**: 対象の設計書・要件定義の所在を確認(docs/design/、ADR等。
   不明なら質問)。作業ブランチと未コミット変更の有無も確認。
1. **タスク洗い出し**: 設計書と現状コードの差分から実装タスク一覧を作る。
   各タスクは「1周回で完了し、検証方法を1文で書けるサイズ」に割る。
   既存の task-list 文書があればそちらへ同期する。
2. **1タスク実施**: テスト先行で実装(software-development-workflow 準拠)。
   規模が大きければ impl-builder に委譲。
3. **レビュー**: review-orchestrator(小差分なら code-reviewer 単体)。
   blocking 指摘は修正してから次へ。
4. **洗い出し更新**: 完了タスクを消し、レビューで発覚した新タスクを追加。
5. **反復**: 残タスクが空になるまで 2〜4 を繰り返す。/loop 運用時は
   workflow-patterns P8 に従い、各周回の冒頭に「残タスク数と前回差分」を1行記録。

終了条件: タスクリスト空+テスト全緑+quality-checklist 通過。
停止条件: 同一タスクで3回失敗したら停止して報告
(test-fixer→bug-investigator→rootcause-auditor の引き継ぎ線に乗せる)。
