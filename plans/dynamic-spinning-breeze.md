# HALO 作成すべき設計書一覧の確定

## Context

`HALO要件定義書.md`(v1.8) と `HALO設計書一覧.md`(D1〜D9 体系) を確認した。既存の `docs/design/01〜06` は **v1.5 時点**の内容(bash ベース、helpers.sh 前提)で書かれており、v1.8 の確定事項(コア TypeScript 化、specs/ 廃止→グラフ一元化、npm 配布)と乖離している。また設計書一覧が定義する D1〜D9 体系と既存 docs/design の構成が一致していない。

## 現状マッピング(D1〜D9 vs 既存文書)

|---|---|---|---|

| D2 コア詳細設計書 | 01/02 が部分カバー(bash 前提で陳腐化) | **v1.8 準拠で再作成** — TS 9モジュール分割、loop 状態機械、runPort、budget、discovery |

## 今回のスコープ(ユーザー確定)

- **優先3点のみ作成**: D1 コントラクト仕様書 / D4 セキュリティ設計書(骨子) / D9 ADR 追補(4本)
- 既存 `docs/design/01〜06` は**素材として改訂**方針(アーカイブせず v1.8 準拠に流用)。今回は D4 作成時に 06 を素材として参照・改訂する
- D2/D3/D8 以降は次ステップ

## 作成順序(設計書一覧の推奨に従う)

1. **D1 コントラクト仕様書** — 最優先、実装着手前
2. **D4 セキュリティ設計書(骨子)** — 初回無人実行前に必須
3. **D9 ADR 追補**(TS化 / グローバル状態ゼロ / specs/廃止 / 数値非固定) + 既存 ADR の v1.8 整合確認
4. **D2 / D3 / D8** — Phase 1 実装と並走
5. D7 → 実運用後、D5 → OSS 公開前、D6 → Phase 4 前

## 付随タスク

- 既存 `docs/design/01〜06` を D1〜D9 体系にどう吸収するか決める(改訂して D2/D4/D6 の素材にする or v1.5 アーカイブ化)
- `docs/design/README.md` の出典が「v1.5」のままなので v1.8 に更新

## 検証

- 各設計書の内容が要件定義書 v1.8 の §11.1(確定)/11.2(初期値)/11.3(保留) 分類と矛盾しないこと
- D1〜D9 の公開/私有区分が要件定義書 2.1 の公開範囲と一致すること
